原道「原点」降噪耳机 · Windows 控制台

连接 TWS 蓝牙耳机后显示设备名称与左右耳独立电量，并直接切换「降噪 / 通透 / 关闭」。基于恒玄 BES2700 方案，技术栈 C#/.NET 8 + WPF。

技术栈 C# · .NET 8 · WPF 蓝牙通道 WinRT GATT 目标设备 原道 OriG in 原点 日期 2026-08-13

01项目概述

1.1 背景

原道 OriG in「原点」是主打高性价比的旗舰降噪 TWS 耳机，搭载恒玄 BES2700 系列蓝牙音频 SoC，支持 55dB 主动降噪、通透模式、入耳检测、LHDC V5 等特性。其降噪切换与左右耳独立电量等能力仅通过厂商「原道 YUANDAO」手机 APP 暴露，Windows 系统本身不提供任何控制入口。本工具在 Windows 桌面补齐这一能力。

1.2 目标

  • 交付可直接运行的 Windows EXE（绿色版，免安装）；
  • 连接 / 识别耳机，显示蓝牙名称与左右耳独立电量；
  • 支持「降噪 / 通透 / 关闭」三态切换；
  • 分层架构清晰、协议可插拔，便于未来适配其他品牌；
  • 代码规范统一，可测试、可维护、可扩展。

1.3 功能需求（FR）

编号需求优先级说明
FR-01蓝牙扫描与列表P0扫描附近设备，过滤出耳机

02技术调研结论

调研覆盖：目标耳机硬件方案、Windows 蓝牙 API 选型、电量与降噪控制协议、UI 技术栈。

2.1 目标耳机硬件方案

项结论
主控 SoC恒玄 BES2700 系列（双模：BR/EDR 音频 + BLE 控制）
编解码LHDC V5，最高 24bit/192kHz
降噪55dB 极限深度，降噪 / 通透通过 APP 切换
配套 APP「原道 YUANDAO」（音效、降噪、入耳检测设置）
入耳检测 / 双设备均有硬件与固件支持

关键推论：

  1. 耳机具备 BLE 通道，控制能力必然通过 BLE GATT 私有服务暴露——官方 APP 即通过 BLE 连接；
  2. BES 方案在国产 TWS 中应用极广，BLE 控制通道有方案级通用性，但原道会定制 UUID 与命令结构，不能直接套用其他 BES 机型的协议；
  3. 私有协议目前无公开文档，需要按第 7 章方法逆向。
⚠ 最大不确定点 — 若原道对 BLE 命令做了加密 / 签名（类似华为 FreeBuds 的加密握手），逆向成本显著上升。落地前必须先完成协议探测（第 7 章）。

2.2 Windows 蓝牙访问选型

方案说明结论
WinRT Windows.Devices.Bluetooth（GATT）官方 API，DualApiPartitioned，桌面应用可用；WPF 通过 net8.0-windows10.0.19041.0 TFM 自动获得投影✅ 采用
Win32 GATT（BluetoothGATTGetServices）底层 C API，P/Invoke 工作量大弃用
InTheHand.Net（32feet.NET）第三方跨平台库，WinRT/LE 支持较弱弃用
btleplug / bleak（其他语言）不适合 C# 选型弃用

WPF 正确引用 WinRT 的关键配置（避免 CS0234「Windows 命名空间不存在」）：

    <TargetFramework>net8.0-windows10.0.19041.0</TargetFramework>  <!-- 关键：带 windows10.x TFM -->
    <UseWPF>true</UseWPF>

    <ImplicitUsings>enable</ImplicitUsings>

Capability 说明：打包（MSIX）应用需在 Package.appxmanifest 声明 <DeviceCapability Name="bluetooth"/>。非打包桌面应用绝大多数 GATT 客户端操作可直接工作；若个别 API 受限，兜底改 MSIX 打包。本项目默认非打包绿色版。

2.3 电量获取方案

通道UUID数据说明
标准 Battery ServiceService 0x180F，Char 0x2A191 字节，0–100%单个合并值；多数 BES 耳机仅在此暴露单耳 / 盒内总电量
厂商私有通道（目标）厂商自定义 128 位 UUID 特征多字节：L / R / 盒真正的左右耳独立电量在这里，需逆向获取

BES 方案常见规律（辅助逆向判断，不保证原道一致）：

  • 私有电量特征通常可 Notify，随电量变化实时推送；
  • 有的只支持 Notify、不支持主动 Read（主动 Read 返回 0x00 的已知坑），因此必须订阅 ValueChanged，不能只靠一次性读取；
  • 读取字节需按特征 PresentationFormats 指数换算（通常无指数，但需校验）。

读取策略：

优先级 1：私有特征（左右耳独立） → 解析 L/R 两个百分比，UI 分耳显示 优先级 2：标准 0x2A19 → 单值，UI 显示为「总电量」，左右耳同值 订阅 Notify：任何通道都订阅，电量变化实时刷新，不轮询

2.4 降噪 / 通透控制方案

结论：无通用标准协议，必须走厂商私有 GATT 特征，先逆向再实现。

案例品牌协议特征参考价值
SonyHeadphonesClient（开源）索尼 WH/WF0x2B 服务，00002b01-… 特征低位 nibble 即 ANC 等级；Windows 侧用 WinUSB 驱动架构、协议解析思路
marshall-protocol（开源）Marshall Motif II私有 UUID 前缀 -1337-1dea-feed-c0ffee70c0de；命令走写特征逆向方法论
华为 FreeBuds 逆向（博客）华为BLE 服务带加密握手 + 会话密钥轮换⚠ 反面教材：加密需评估成本

模式枚举（领域层）：

public enum NoiseCancellingMode
{
    Unknown = 0,
    Off,           // 关闭（普通模式）
    AncOn,         // 降噪
    Transparency,  // 通透（环境声）
}

具体字节值（如 Off=0x00 / ANC=0x01 / Transparency=0x02）在逆向后写入对应品牌适配器，领域层不感知。

03总体架构

3.1 设计原则

  1. 依赖倒置：跨层依赖指向 Domain 中定义的接口；
  2. 单向依赖：Presentation → Application → Domain；Infrastructure/Protocol 向上实现接口，禁止回环；
  3. 协议可插拔：品牌相关一切隔离在 Protocol 适配器内，领域与界面零感知；
  4. 硬件无关：WinRT 只出现在 Infrastructure 适配层，核心逻辑可脱离真机测试。

3.2 分层架构

┌─────────────────────────────────────────────────────────────┐ │ Presentation 层（WPF 界面） │ │ Views / ViewModels / 托盘 / 绑定 / 事件转发 │ └───────────────────────────┬─────────────────────────────────┘ │ 调用用例 ┌───────────────────────────▼─────────────────────────────────┐ │ Application 层（用例编排） │ │ HeadsetConnectionService / BatteryMonitorService │ │ NoiseCancellingService / 会话管理 / 重连调度 │ └───────────────────────────┬─────────────────────────────────┘ │ 依赖领域接口 ┌───────────────────────────▼─────────────────────────────────┐ │ Domain 层（领域模型 + 接口，纯 C#，无 UI / 无 WinRT） │ │ HeadsetDevice / BatteryInfo / NoiseCancellingMode │ │ IHeadsetConnection / IBatterySource / INoiseControlSource │ └───────────────────────────▲─────────────────────────────────┘ │ 实现接口（依赖倒置） ┌───────────────────────────┴─────────────────────────────────┐ │ Infrastructure 层（蓝牙硬件访问 + 协议适配） │ │ ┌─────────────┐ ┌─────────────────────────────────────┐ │ │ │ WinRT 适配器 │ │ Protocol 适配器（可插拔） │ │ │ │ DeviceWatcher│ │ StandardProtocol / BESProtocol │ │ │ │ GattClient │ │ YuandaoProtocol（逆向后填充） │ │ │ └─────────────┘ └─────────────────────────────────────┘ │ └─────────────────────────────────────────────────────────────┘

3.3 依赖方向

  • 允许：上 → 下（Presentation→Application→Domain）；Infrastructure→Domain；
  • 禁止：Domain 引用上层或 WinRT；Application 不引用 WPF / WinRT 具体类型；
  • 跨层对象一律使用 DTO / 领域模型，禁止把 WinRT 类型（BluetoothLEDevice、GattCharacteristic）传出 Infrastructure。

3.4 核心数据流

电量数据流：

GATT Notify 事件 → Infrastructure 蓝牙适配器（解析原始帧） → Protocol.YuandaoProtocol（解析出 BatteryInfo { L, R, Case }） → Domain 领域模型 → Application.BatteryMonitorService（缓存 + 变更事件） → Presentation ViewModel（PropertyChanged → 绑定刷新）

降噪切换数据流：

ViewModel 选择模式 → Application.NoiseCancellingService.SwitchAsync(mode) → Protocol.YuandaoProtocol.BuildAncCommand(mode) → 字节帧 → Infrastructure GattClient.WriteAsync(私有特征, 帧) → 耳机返回 → Protocol 解析确认 → ViewModel 更新 UI

3.5 线程模型

  • UI 线程：仅 WPF 绑定与事件转发，变更通过 Dispatcher 调度；
  • 蓝牙 IO：WinRT 异步 → async/await，不阻塞 UI；
  • Notify 回调：可能不在 UI 线程，由 Application 层聚合发布，ViewModel 封送；
  • 规则：全链路 await，禁止 async void（事件处理器除外且必须 try/catch）；禁止 .Result / .Wait()。

4.2 核心接口设计（Domain 层）

// 设备协议：一个品牌一套实现，可插拔
public interface IDeviceProtocol
{
    Guid ServiceUuid { get; }                       // 私有控制服务 UUID
    BatteryInfo? TryParseBattery(byte[] frame);     // 解析电量帧（L/R/盒）
    byte[] BuildAncCommand(NoiseCancellingMode mode);  // 构造降噪切换命令
    NoiseCancellingMode? TryParseAncState(byte[] frame); // 解析当前降噪状态
    bool IsAncStateNotification(Guid characteristicUuid);
    bool Matches(HeadsetDevice device);             // 匹配判定
}

// 电量来源抽象（标准通道与私有通道都实现，支持优先级叠加）
public interface IBatterySource
{
    Task<BatteryInfo?> ReadOnceAsync(CancellationToken ct);
    IObservable<BatteryInfo> BatteryChanged { get; }   // Notify 订阅流
}

// 降噪控制抽象
public interface INoiseControlSource
{
    Task<NoiseCancellingMode> GetModeAsync(CancellationToken ct);
    Task SetModeAsync(NoiseCancellingMode mode, CancellationToken ct);
    IObservable<NoiseCancellingMode> ModeChanged { get; }
}

4.3 电量读取策略

BatteryMonitorService 聚合两条通道：

  1. 连接后枚举 GATT 服务表（BluetoothCacheMode.Uncached 防陈旧）；
  2. 发现私有服务 UUID → 注册私有电量特征，走 YuandaoProtocol；
  3. 同时注册标准 0x2A19 兜底；
  4. 收到 Notify 帧按「私有优先」刷新 UI；
  5. 订阅失败退化为定时读取（间隔 ≥ 30s）。

4.4 降噪协议适配器

YuandaoProtocol : BESProtocolBase, IDeviceProtocol。UUID 常量与字节映射在逆向后填入；逆向完成前抛 ProtocolNotResolvedException。命令流程：先使能通知 → 写命令 → 等待确认帧（带超时）；写后回读当前模式确认，失败则提示，避免 UI 假成功。

4.5 状态机与重连

Disconnected ──连接──▶ Connecting ──成功──▶ Connected ▲ │失败 │ └──── 重连(退避) ───────┴──────── Notify 断开 ──▶ Reconnecting

断开自动重连（指数退避 1s→2s→4s，上限 30s）；重连后恢复电量订阅并回读降噪模式同步 UI；状态变化以事件发布。

4.6 配置与持久化

  • appsettings.json：日志级别、重连参数、协议开关；
  • 用户配置：%LocalAppData%\YuandaoTws\config.json（记住上次设备、默认模式）；
  • 无数据库。

5.3 分层职责边界（红线）

层允许禁止
Presentation绑定、ViewModel、命令触发、UI 调度直接调用 WinRT；解析蓝牙帧
Application用例编排、会话 / 缓存 / 重连引用 WPF / WinRT 类型；写解析逻辑
Domain领域模型、枚举、接口、纯算法引用任何 UI / WinRT / 基础设施类型
InfrastructureWinRT 封装、字节 IO、协议解析反向依赖上层；包含业务用例

判定法：任意层文件的 using 不得出现其下方各层命名空间；using Windows.* 只允许出现在 Infrastructure。

5.4 异步规范

  • async/await 全链路，禁止 .Result / .Wait()；
  • 库代码 ConfigureAwait(false)；事件处理器 async void 必须 try/catch；
  • 可取消操作一律接受 CancellationToken；
  • GATT 读写设超时（CancelAfter），防止永久挂起。

5.5 错误处理与日志

  • 自定义异常体系：DomainException、BluetoothConnectionException、ProtocolException、ProtocolNotResolvedException；
  • 分层捕获：Infrastructure 抛领域化异常，Application 记录日志，Presentation 转 UI 提示；
  • 禁止空 catch 吞异常；异常必须含上下文（设备、UUID、操作、帧 hex）；
  • 日志级别：Debug（帧级）/ Info（状态）/ Warn（重连、降级）/ Error（异常）；
  • 电量帧解析失败记录完整 hex 帧，便于逆向校准。

5.6 单元测试规范

  • xUnit + NSubstitute（Mock）+ FluentAssertions；
  • 协议解析逻辑 100% 覆盖，用真机抓包帧做测试数据；
  • Domain 测试不依赖硬件；Infrastructure 用接口隔离测试字节流处理；
  • 覆盖率目标：Domain ≥ 80%，Application ≥ 60%。

5.7 代码评审清单

  • 依赖方向是否符合分层红线？
  • WinRT 类型是否泄漏出 Infrastructure？
  • 是否存在 async void 未捕获、.Result、空 catch？
  • 协议解析是否覆盖异常帧（长度不足、超界值）？
  • 是否补充了对应单元测试用例？

07协议逆向方案（关键前置任务）

⚠ 前置门禁 — 降噪切换与双耳电量的私有协议必须先逆向。本阶段交付「协议探测工具 + 协议文档」，通过后才能进入功能开发。预计 3–5 个工作日。

7.1 目标

  1. 枚举耳机完整 GATT 服务 / 特征表；
  2. 定位：双耳电量特征、降噪控制写特征、降噪状态通知特征；
  3. 得出命令字节结构与电量帧格式，形成 docs/protocol/yuandao-origin.md。

7.2 工具链

工具用途
Android（开发者模式）开启「蓝牙 HCI 抓包日志」，配合原道 APP 抓包
adb导出 btsnoop_hci.log
Wireshark解析 HCI/ATT/GATT
nRF Connect（Android）免 APP 直连耳机，浏览 / 读写特征
JADX反编译原道 APK，提取 UUID 与命令构造代码
本项目 tools/（Python bleak）在 Windows 上重放命令、批量验证

7.3 操作步骤

A. 抓包（Android HCI Snoop）

  1. 开发者选项开启「蓝牙 HCI snoop 日志」；
  2. 原道 APP 连接耳机，依次执行：查看电量 → 降噪 → 通透 → 关闭；
  3. adb pull /sdcard/btsnoop_hci.log；
  4. Wireshark 过滤器：发现 btatt.opcode == 0x08 || 0x10，写入 0x12 || 0x52，通知 0x1b || 0x1d。

B. 反编译 APK（JADX）

  • 搜索 writeCharacteristic、setCharacteristicNotification；
  • 搜索 128 位 UUID 字符串；
  • 观察命令构造（是否 base64、是否带签名——判断是否加密的关键）。

C. 实测核对（nRF Connect）：直连耳机，对照记录逐一浏览服务表；手动写入候选命令，观察降噪是否变化。

D. 重放验证：Windows 端 Python bleak 脚本重放降噪切换与电量读取，确认可稳定复现；帧样例作为单测数据。

7.4 阶段交付物

  • docs/protocol/yuandao-origin.md：UUID 表、命令表、电量帧格式；
  • tools/probe.py：Windows 端探测 / 重放脚本；
  • 测试用例帧数据（L/R 电量、三态降噪各一帧）。

7.5 决策点

探测结果后续决策
命令明文可重放✅ 正常开发，适配器按协议实现
命令带简单校验（CRC/校验和）✅ 补校验算法
命令带加密 / 签名 / 会话密钥⚠ 评估成本，可能仅实现电量或暂停

08开发计划

里程碑内容周期
M0 协议逆向逆向全流程，产出协议文档3–5 天
M1 工程骨架 + 连接分层工程、DI、扫描 / 连接 / 断开、显示设备名2–3 天
M2 电量显示标准通道先行，私有通道按 M0 接入，Notify 实时刷新2–3 天
M3 降噪切换私有命令接入、模式回读、失败回滚2–3 天

首周任务：

  • 建立 5 层工程骨架与 .editorconfig、CI 构建脚本
  • Domain 层接口与模型 + 单元测试
  • 蓝牙扫描与连接（DeviceWatcher + BluetoothLEDevice）
  • 标准 0x2A19 电量读取与 Notify 订阅（兜底通道）
  • 并行启动 M0 协议逆向（抓包 + 反编译）
  • 实现 tools/probe.py 探测脚本

09风险与应对

#风险影响应对
1私有协议未公开，逆向周期不可控高M0 前置，探测不通过不排期 M2/M3
2命令可能加密高逆向阶段判定；加密则降级范围或协商
3双耳电量仅 Notify 不 Read中统一订阅通道；兜底显示
4非打包应用 WinRT 受限低兜底 MSIX 打包发布
5固件升级协议漂移低记录固件版本，适配器版本化
6扫描不到 BLE 设备中文档注明首次使用先在 Windows 蓝牙设置配对
